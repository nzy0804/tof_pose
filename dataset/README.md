# tof_pose 数据集规范

本文档用于约束 `tof_pose` 项目的姿态估计数据集整理方式，默认面向 `YOLO pose` 训练流程。

## 推荐目录结构

```text
dataset/
  images/
    train/
    val/
    test/
  labels/
    train/
    val/
    test/
  meta/
    manifest.csv
  dataset.yaml
  README.md
```

目录说明：

- `images/train/`：训练集图像
- `images/val/`：验证集图像
- `images/test/`：测试集图像，可选
- `labels/*/`：与图像同名的 YOLO pose 标签文件
- `meta/manifest.csv`：抽帧来源记录，方便回溯原始视频
- `dataset.yaml`：训练配置文件

## 图像与标签命名规范

建议统一命名为：

```text
<视频名>_f<帧号六位>.jpg
<视频名>_f<帧号六位>.txt
```

示例：

```text
session01_f000120.jpg
session01_f000120.txt
```

要求：

- 同一张图像与标签文件必须同名，仅扩展名不同
- 文件名只使用字母、数字、下划线，避免空格和中文路径
- 不同视频抽帧后不要出现重名文件

## 标注格式

当前项目建议使用 `YOLO pose` 标签格式，每行对应 1 个人：

```text
class x_center y_center width height x1 y1 v1 x2 y2 v2 ... x17 y17 v17
```

说明：

- `class`：人体类别，通常为 `0`
- 检测框和关键点坐标均使用相对图像宽高归一化后的数值
- `v` 为关键点可见性，常用约定：`0=未标注`，`1=遮挡但可估计`，`2=可见`
- `17` 个关键点顺序建议与 COCO 关键点顺序保持一致

## 关键点顺序

```text
0  鼻子
1  左眼
2  右眼
3  左耳
4  右耳
5  左肩
6  右肩
7  左肘
8  右肘
9  左腕
10 右腕
11 左髋
12 右髋
13 左膝
14 右膝
15 左踝
16 右踝
```

## 数据采集建议

建议优先覆盖以下情况：

- 单人、双人、多人同框
- 近距离、中距离、远距离
- 正面、侧身、转身、背身
- 抬手、弯腰、蹲下、行走
- 人体局部遮挡、多人交叉遮挡
- 深度轮廓清晰和轮廓模糊两类情况

对连续视频抽帧时，避免保留大量几乎重复的画面。

## 划分建议

推荐比例：

- 训练集 `70%`
- 验证集 `20%`
- 测试集 `10%`

更重要的原则：

- 尽量按“视频段”划分，而不是把同一段连续视频拆散到多个集合
- 同一场景下连续帧不要同时大量进入训练集和验证集，否则验证结果会偏乐观

## 标注检查清单

开始训练前，至少检查以下项目：

- 每张图像都存在同名标签文件
- 标签文件中每一行字段数正确
- 类别 id 统一为人体类别 `0`
- 检测框坐标均在 `0~1` 范围内
- 关键点坐标均在 `0~1` 范围内
- 关键点左右没有标反，尤其是侧身场景
- 遮挡点的可见性标记合理，没有把看不见的点强行标成可见
- 多人场景中，每个人的框和关键点没有串人
- 明显失真的深度图、严重拖影帧、几乎全黑帧已剔除
- 训练集和验证集中的场景没有过度重复

## 当前项目的特别建议

由于 `tof_pose` 当前实时推理使用的是深度图伪彩映射结果：

- 训练图像最好也统一使用同样的伪彩风格
- 如果以后要做更稳定的距离估计，建议额外保留原始深度数据与图像文件的对应关系
- 若后续准备做离线距离回放，建议在 `meta/` 中记录原始视频、抽帧索引和时间戳

## 抽帧脚本

项目已提供：

```powershell
python scripts/prepare_dataset.py --input outputs/videos --dataset-root dataset --sample-every 5
```

这个脚本会：

- 扫描输入视频
- 创建标准训练目录
- 按视频划分 train / val / test
- 按固定间隔抽帧
- 自动生成同名空标签文件
- 生成 `dataset/meta/manifest.csv` 和 `dataset/dataset.yaml`
